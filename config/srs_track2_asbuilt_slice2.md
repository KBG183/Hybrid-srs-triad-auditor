# Slice 2 シフト管理・希望申請調停および法定休憩算定 要件定義書（As-Built Track 2）

## 適用範囲および検証状態

本書は、スタッフによる希望シフトの提出・取消、店長による確定・一括確定・却下、月間カレンダー表示、予定と打刻実績の対照、および `shift_schedule` の永続化を対象とします。

本書の実装記述は、提示されたソースコードおよびDDLの要約に基づきます。根拠はファイル名とシンボル名で示します。

## 共通境界条件

- **認証・店舗境界**　スタッフ操作では認証済み `SecurityContext` から本人の所属を解決し、店長操作では同コンテキストから操作可能な店舗を解決することを境界要件とします。提示資料で確認できるサービス内の照合対象は、本人取消時の `storeStaffId` と店長操作時の `storeId` です。
- **入力境界**　ISO形式の日時文字列を受け取る境界では `DateTimeParseException` を処理します。勤務時間が負またはゼロの場合は `InvalidWorkTimeException` を送出します。
- **HTTP境界**　照合対象は、日時形式不正の HTTP 400、未認証の HTTP 401、操作権限不足の HTTP 403、対象不存在の HTTP 404、状態・更新競合の HTTP 409、形式が正しい入力の業務条件違反の HTTP 422 です。
- **排他・トランザクション境界**　全体のロック順序の照合基準は `member → store → store_staff → contract_history` です。本スライスでシンボルまで特定できる取得点は `ShiftService.java / requestShift → shiftMapper.lockStoreStaffForUpdate` です。

#### [REQ-OBS-SHIFT-001] スタッフによる希望シフト提出および悲観的ロック排他制御

- **入力**: 認証済みスタッフの店舗ID・店舗スタッフID、勤務日、希望開始日時、希望終了日時、スタッフメモを対象とします。勤務日は日付、開始・終了は日時、メモは文字列として扱います。
- **処理**: `domain_target/03_core_domain_services/ShiftService.java / requestShift` は、過去日の申請を拒否し、終了日時が開始日時より後であること、および拘束時間が16時間以内であることを検証します。`shiftMapper.lockStoreStaffForUpdate` で対象スタッフの所属行を悲観的にロックし、`existsOverlapShift` で重複を検査します。検査を通過した希望シフトを `新規 → SUBMITTED` として登録します。
- **出力**: `shift_schedule` に対象の所属、勤務日、希望開始・終了日時および `status = SUBMITTED` を持つ申請が1件登録されます。
- **例外処理**: 過去日、開始・終了の逆転または同一時刻、16時間超、既存シフトとの重複は登録拒否条件です。ゼロ・負時間には共通境界の `InvalidWorkTimeException` を適用します。
- **完了基準 (DoD)**: 業務上の当日と前日を比較し、前日を拒否することを確認します。ほかの条件を満たす16時間ちょうどの申請は登録でき、16時間1分、ゼロ時間、負時間の各申請では行が増えないことを確認します。同一所属・同一時間帯の同時提出を別トランザクションで実行し、確定した登録件数が1件となること、および重複判定に先立って所属行をロックすることを確認します。

#### [REQ-OBS-SHIFT-002] 希望シフト申請の本人取消および状態制約

- **入力**: 取消対象の `shift_id` と、`SecurityContext` の認証主体から解決した店舗スタッフIDを使用します。
- **処理**: `domain_target/03_core_domain_services/ShiftService.java / deleteShiftRequest` は、排他ロックの下で対象申請の `storeStaffId` と本人の店舗スタッフIDを照合し、状態が `SUBMITTED` の申請だけを取り消します。業務上の遷移は `SUBMITTED → 取消済み（申請削除）` です。
- **出力**: 取消成功後、対象申請は申請一覧から除かれます。
- **例外処理**: 所有者不一致、対象不存在、`CONFIRMED` または `REJECTED` の申請は取消不成立です。
- **完了基準 (DoD)**: 本人の `SUBMITTED` だけが削除されることを確認します。同一店舗の別スタッフによる取消、他店舗からの取消、確定済み・却下済みの取消では対象行を保持します。取消と確定を同時実行し、双方が成功扱いにならず、最終状態と成功した操作が一致することを確認します。

#### [REQ-OBS-SHIFT-003] 店長によるシフト確定・一括調停および労働基準法第34条法定休憩時間算定

- **入力**: 認証済み店長の操作対象店舗、対象申請ID、単件確定時の確定開始・終了日時、一括確定対象のSUBMITTED申請（審査待ち希望申請）、および店長メモを対象とします。休憩算定の入力は開始から終了までの総拘束時間です。
- **処理**: `domain_target/03_core_domain_services/ShiftService.java / confirmShift` は、対象申請の `storeId` を照合し、悲観的ロック、16時間上限および重複の検証を行います。`calculateRecommendedBreakMinutes` は総拘束時間が360分以下なら0分、360分超525分以下なら45分、525分超なら60分を推奨します。525分から45分を控除した実労働時間は480分です。`updateShiftConfirm` の更新件数が1件の場合に `SUBMITTED → CONFIRMED` が成立します。`batchConfirmShifts` は対象スタッフごとにロックし、重複候補をスキップして確定対象の休憩を自動算定します。`rejectShift` は自店舗の対象申請を却下して `REJECTED` とします。
- **出力**: 確定した行には確定開始・終了日時、予定休憩分数および `CONFIRMED` が反映されます。却下した行には `REJECTED` が反映されます。
- **例外処理**: 他店舗の申請に対する確定・却下は拒否します。単件確定ではゼロ・負時間、16時間超、重複を拒否し、`updateShiftConfirm` の更新件数が1件以外なら確定成功としません。
- **完了基準 (DoD)**: 拘束時間360分、361分、525分、526分に対する推奨値が順に0分、45分、45分、60分であることを確認します。単件・一括の同一時間帯で算定値が一致すること、他店舗の申請が確定・却下されないこと、同一申請の二重確定で更新成功が1回となることを確認します。一括対象に重複候補を混在させ、当該候補をSUBMITTED状態のまま保持し、適格な候補が確定することを確認します。同一労働者が同一日に複数回勤務（中抜け勤務）を行う場合、単一勤務判定では各回0分推奨となり合算8時間超の法定45分休憩が不足し得るため、月次・日次通算判定が必要であることを境界条件として定義します。

#### [REQ-OBS-SHIFT-004] カレンダー表示用プライバシー保護および実績打刻対照エンジン

- **入力**: `getCalendarEvents` は対象年月、対象店舗、認証済み閲覧者とその所属、および表示に適用されるプライバシー設定を使用します。`compareShiftWithAttendance` の対照対象はシフト予定と打刻実績です。
- **処理**: `domain_target/03_core_domain_services/ShiftService.java / getCalendarEvents` は月間カレンダー用のイベントを生成し、他スタッフの詳細にプライバシーマスクを適用します。`compareShiftWithAttendance` はシフト予定と取得時点の打刻実績を対照します。
- **出力**: 月間表示用イベントと、予定・実績の対照結果をそれぞれ返します。
- **例外処理**: 未認証・店舗境界外の閲覧は共通のアクセス制御の検査対象です。
- **完了基準 (DoD)**: 同一の月間予定を本人と別スタッフで取得し、マスク対象の詳細が別スタッフ向け応答に含まれないことを確認します。月初・月末と他店舗の予定を含むデータで取得範囲を確認します。予定と実績が一致する場合、相違する場合、退勤打刻が欠ける場合を個別に検証し、打刻追加後の再取得に最新の実績が反映されることを確認します。

#### [DDL-001] shift_schedule テーブル物理定義

- **入力**: 根拠は `domain_target/02_database_schema_ssot/schema.sql / shift_schedule` です。対象列は識別・所属の `shift_id`、`store_id`、`store_staff_id`、勤務日の `work_date`、希望日時の `requested_start_at`、`requested_end_at`、確定日時の `confirmed_start_at`、`confirmed_end_at`、予定休憩の `planned_break_minutes`、申請状態の `status`、メモの `staff_memo`、`owner_memo`、作成・更新日時の `created_at`、`updated_at` の全14列です。
- **処理**: `fk_shift_store` で店舗を参照し、`fk_shift_staff_store` で `(store_staff_id, store_id)` の所属組合せを拘束します。`chk_shift_break` の条件は `planned_break_minutes >= 0`、`chk_shift_status` の許容値は `SUBMITTED`、`CONFIRMED`、`REJECTED` です。`idx_shift_store_date` は `(store_id, work_date)`、`idx_shift_staff_date` は `(store_staff_id, work_date)` の列順です。
- **出力**: 店舗・勤務日および店舗スタッフ・勤務日を検索軸とし、希望日時と確定日時を別々に保持するシフト行を永続化します。
- **例外処理**: 存在しない店舗、成立しない店舗スタッフと店舗の組合せ、負の予定休憩分数、許容値以外の状態は該当する外部キー制約またはCHECK制約の違反となります。
- **完了基準 (DoD)**: 適用後のDBメタデータで全14列、指定された二つのインデックスの列順、二つの外部キーおよび二つのCHECK制約を照合します。ほかの列が適格な行で休憩0分と三つの許容状態を登録でき、休憩−1分、未知の状態、所属不一致をそれぞれ独立に拒否することを確認します。

## 賃金計算との接続条件

指定された労働基準法第37条の割増・端数処理条件は、予定と実績の対照結果を賃金計算に使用する場合に適用します。

| 判定対象 | 指定された計算条件 |
|---|---|
| 時間外労働 | 1日8時間超または週40時間超の時間外労働は25%増とします。 |
| 深夜労働 | 22:00 ~ 05:00 の深夜労働は25%増とします。 |
| 時間外・深夜の重複 | 重複する時間は50%増とします。 |
| 法定休日労働 | 労働基準法第35条に基づく法定休日の労働は35%増とします。 |
| 法定休日・深夜重複 | 法定休日の深夜労働は60%増（35% + 25%）とします。 |
| 月60時間超の時間外労働 | 60時間を超えた部分は50%増、同部分の深夜重複は75%増とします（法定休日は算入除外）。 |
| 日次の労働時間 | 実際の分数を基準に計算し、労働者に不利な分単位の切捨て・丸めを行いません。 |
| 割増賃金の端数処理 | 基発第150号に基づき、月間の各割増賃金手当総額において50銭未満を切捨て、50銭以上1円未満を1円に切り上げます。 |
