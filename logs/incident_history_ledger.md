## 2. 運用障害および再発防止台帳 (Incident History)

### 2026-11-17 — INCIDENT-56 — PowerShell構文例外後のバックグラウンドタスク無応答およびプロセス残留の防止

- **問題**: 診断コマンドの非同期呼び出し時における標準入力待ちやサブシェル変数展開エラーにより、バックグラウンドタスクが残留・無応答化する現象が発生。
- **原因**: 診断系コマンドにおける同期待ち時間（WaitMsBeforeAsync）の不足、および標準入力を伴うインラインパイプラインの実行。
- **再発防止ガードレール**:
  1. 状態照会・診断系コマンドは `WaitMsBeforeAsync: 10000` を指定し、確実な同期完了を担保。
  2. コード監査・検証は、タイムアウト・ハートビート監視を備えた検証済み単一ランナー（`audit_with_hermes.ps1`）のみを経由。
  3. 未完了バックグラウンドプロセスの残留を定期監視し、発見時は即時遮断するFail-Closed運用を徹底。
- **状態**: `RESOLVED_PERMANENT_RULE_ENFORCED`

### 2026-11-17 — INCIDENT-55 — C#決定論的リンター v1.1 の実装・コンパイルおよび全仕様ブロック（8件）の機械的検証完了

- **問題**: 初期リンターが単純な書式検査にとどまり、エンタープライズ要件定義書の構造的完全性および基本セキュリティ制約の検証能力が不足していた。
- **原因**: プロトタイプ実装から本格業務検証エンジンへの移行未着手。
- **再発防止ガードレール**:
  1. `VerifySRS_Deterministic.cs` を147行の本格C#エンジン（v1.1）へ刷新（5大必須項目・IDORパラメータ機械遮断・状態遷移矢印構文の強制）。
  2. コンパイルおよび `config/srs_specification_ssot.md` 全8要件に対する実行検証を行い、FATAL=0, WARNING=0（0.05秒）の完全整合性を実証。
- **状態**: `RESOLVED_COMPILED_AND_VERIFIED`

### 2026-11-17 — INCIDENT-54 — C#決定論的リンターにおける正規表現オーバーフィッティングの限界是正と2-Tierアーキテクチャの確立

- **問題**: 労働基準法や端数処理等の複雑なドメイン数式（`0.25`, `HALF_UP`等）をC#正規表現で直接検証しようとすると、自然言語の同義語（「25%割増」）による誤検知（False Positive）や、単語を含むだけの無効数式の見逃し（False Negative）が発生する設計的脆弱性を露呈。
- **原因**: 決定論的リンターとLLM推論モデルの責務境界の混同。
- **再発防止ガードレール**:
  1. 決定論的C#リンターは「構文・5大必須セクション・IDORパラメータ機械遮断・状態遷移矢印」等の構造的・セキュリティ不変条件のみをFail-Closedで高速検証（0.05秒）。
  2. 数式・計算順序・労働法規の文脈意味論的妥当性は3核AI（Qwen/Codex/Claude）交差監査に委ねる明確な2-Tier責務分担を確立。
- **状態**: `RESOLVED_ARCHITECTURE_ESTABLISHED`

### 2026-11-17 — INCIDENT-53 — 3核AI（Qwen/Codex/Claude）交差監査によるSlice 1のP0欠陥の即時是正

- **問題**: [Slice 1] 店舗・会員管理仕様において、スタッフ招待承諾時の時給・交通費自己決定権の露出、ロール直接指定による権限昇格リスク、複数店舗認可ガード欠落の脆弱性が3核AI監査により検出された。
- **原因**: 初期仕様における認可境界の甘さおよび権限昇格防御の考慮不足。
- **再発防止ガードレール**:
  1. 時給・交通費設定を管理者（オーナー）承認専用エンドポイントへ完全隔離。
  2. 一般登録時は `ROLE_STAFF` 固定とし、オーナー登録は専用セキュアエンドポイントへ分離。
  3. 全店舗スコープAPIに `@PreAuthorize("@storeAuth.canAccess(#storeId)")` を強制し、DTOから直接受領するIDを全廃。

### 2026-11-16 — INCIDENT-47 — PowerShell UTF-8 保存時の BOM 付与による Java コンパイル障害の解消

- **問題**: ソース変換スクリプト適用後、`./gradlew compileJava` 実行時に13件の Java ソースファイルで `illegal character: '\ufeff'` が発生しビルドが中断。
- **原因**: PowerShell 標準の `.NET UTF-8` 出力がファイル先頭に3バイトのBOM（Byte Order Mark）を自動挿入し、Java コンパイラ（`javac`）がこれを不正文字として拒否。
- **再発防止ガードレール**:
  1. Java ソースコード保存時は BOM なし UTF-8（`[System.Text.UTF8Encoding]::new($false)`）を強制規格として適用。
  2. 全対象ファイルのBOMを一括除去し、Gradle ビルドおよびテストの完全成功を検証。
- **状態**: `RESOLVED_PERMANENT_RULE_ENFORCED`

### 2026-11-16 — INCIDENT-44 — 入力パイプライン無応答および evidence.html CSP遮断障害の解消

- **問題**:
  1. プレゼンテーションプロトタイプ（スライド19）から証跡資料を開いた際、`evidence.html` のインラインスクリプトCSPハッシュ不整合によりブラウザがスクリプト実行を遮断し、プレビュー本文が白紙になる障害が発生。
  2. 監査スクリプト実行時、標準入力をパイプラインで直接接続したことでEOF未終了によるプロセス無応答（Hang）が発生。
- **原因**:
  1. 改行コード（LF/CRLF）およびスクリプト更新後のCSPメタタグ内SHA-256ハッシュ同期漏れ。
  2. 検証済みの標準ラッパー（`hermes_controller.ps1`）を介さず、任意のコマンドラインパイプラインを実行したことによる入力待機デッドロック。
- **再発防止ガードレール (Permanent Guardrails)**:
  1. **CSPハッシュの多重定義・整合化**: スクリプト改行（LF/CRLF）に対応するSHA-256ハッシュをCSPメタタグに明示し、ブラウザ遮断を100%解消。
  2. **標準インターフェースの強制**: すべての監査・検証スクリプトは、ハートビート監視とタイムアウト処理を備えた検証済みラッパー（`hermes_controller.ps1` / `call_codex.ps1`）を唯一の実行経路とする運用規約を策定（`GEMINI.md` 第4節）。
- **状態**: `RESOLVED_PERMANENT_RULE_ENFORCED`
