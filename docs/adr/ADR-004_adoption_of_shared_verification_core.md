# ADR-004: 事前検証済み共通検証コアのSRSプロファイル移植および単一進入点マスターゲートの採用

- **ステータス**: ACCEPTED (承認済み)
- **決定日**: 2026-11-23
- **意思決定者**: プロジェクト統括アーキテクト
- **関連要件**: 全要件（REQ-AUTH, REQ-ATT, REQ-SETTLE, REQ-INTEG）および検証パイプライン全体

---

## 1. 背景およびコンテキスト (Context)

KINTAI アルバイト勤怠・給与管理SaaSの要件定義において、第4スライス（労働基準法第37条割増賃金計算、悲観的ロックによる二重打刻防止、複数店舗配賦）に突入するにあたり、極めて高精度な無欠性が求められる局面を迎えた。

従来のパイプライン（v1.2）では以下の構造的リスクが識別された：
1. **個別ツールの手動実行（Soft-Gate）**: リンター、AI監査、SSOT反映が個別のスクリプトとして存在し、作業者の失念やステップのバイパスを機械的に遮断できない。
2. **非フェイルクローズド（Non-Fail-Closed）の脆弱性**: 検証対象が0件の場合や未知のエラー発生時に、正常終了と誤認されるリスク。
3. **ルール肥大化によるコンテキスト圧迫**: 42KBに及ぶ詳細ルールがプロンプトへ展開され、LLMの推論リソースを浪費し幻覚（Hallucination）を誘発する懸念。

## 2. 意思決定 (Decision)

事前研究および実運用実績（7日間の稼働実績および10種の単体テスト群）を持つ**「共通検証コア（Shared Verification Core）」**を、開放閉鎖原則（OCP）に基づいてKINTAI SRSドメインプロファイルへ適合・移植することを決定した。

具体的には以下の4大基盤を配備する：
1. **単一進入点シリアルマスターゲート（`gate_master_srs.ps1`）**:
   - `事前点検 ➔ 規格検証 ➔ 最終承認` の直列3段階パイプライン。
   - 厳格な終了コード契約（0: 合格, 1: 事前点検失敗, 2: 規格違反, 3: 承認拒否, 4: 整合性違反）。
   - `-SkipAi` 実行時の正本承認トークン発行遮断。
2. **第0条 SRS 絶対憲法（`ARTICLE_0_SRS.md`）およびSHA-256ハッシュロック**:
   - 冗長ルールを約2.1KBの不可変高密度規則へ圧縮。
   - SHA-256ハッシュ照合による改ざん検知（改ざん時はExit 4遮断）。
3. **外部指摘事項追跡キュー（`srs_pending_findings.json`）**:
   - 外部監査の指摘を物理キューへ登録し、`PENDING=0` かつ `RESOLVED=0`（全件VERIFIED移行）でなければ承認を遮断する2-Tier是正運用の適用。
4. **多層AIハイブリッド交差検証の先行実施**:
   - OpenAI Codex, Anthropic Claude, ローカルQwen 27B, C#決定論的リンターの4層による事前交差監査を実施し、適合性を完全立証。

## 3. 効果と影響 (Consequences)

### ポジティブな影響
- **機械的強制力の確立**: 検証にパスしない限り承認原書（`approval_manifest.json`）が発行されず、不完全な要件の確定が物理的に遮断される。
- **推論効率の大幅向上**: 憲法ルールの圧縮によりプロンプトトークンを大幅に削減し、LLMの幻覚発生率を極小化。
- **客観的エビデンスの担保**: 4層交差監査レポート（`audit/runs/`）および実測実行メトリクス（1,060ms）により、第3者に対する完全な説明責任を果たす。

### 留意事項・運用コスト
- 新規要件の追加時は、必ず `gate_master_srs.ps1` を経由して全自動検証を通過させる必要がある。
- 第0条憲法を変更する場合は、正式な改定手続きとハッシュ再生成（SHA-256）を必須とする。
