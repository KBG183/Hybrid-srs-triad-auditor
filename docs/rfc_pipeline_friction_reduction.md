# RFC-001: KINTAI 検証パイプライン摩擦低減および自律運用効率化仕様書

## 適用範囲および検証状態

本書は、KINTAI プロジェクトにおける多層 AI ハイブリッド交差検証システムおよび要件定義書（SRS）運用において顕在化した「4大逆説的課題」（決定論的ハードゲートの摩擦力、多層AIの過剰監査、デュアルトラック運用保守の二重負担、ローカルインフラの単一障害点）に対する構造的改善仕様を規定します。

本書の改善記述は、運用実績（`logs/incident_history_ledger.md`、`audit/runs/`）、現行規約（`GEMINI.md`）、外部監査官（OpenAI Codex、Anthropic Claude、Local Qwen 27B）の指摘事項、および検証スクリプト群（`tools/scripts/`）に基づきます。根拠は規約条項名およびスクリプトファイル名で示します。

## 共通境界条件

- **認証・統括境界**: 本 RFC に基づくパイプライン改修は、Antigravity（Gemini）の統括オーケストレーションの下で段階的に適用され、事前の決定論的リンター検証を必須とします。
- **入力不変性境界**: 監査実行開始時に監査対象ファイルの SHA-256 ハッシュを固定記録し、ステージ間でのファイル変更や競合による検査対象の乖離（TOCTOU）を Fail-Closed で遮断します。
- **後方互換性境界**: 改善後のパイプラインにおいても、第0条 SRS絶対憲法（`governance/ARTICLE_0_SRS.md`）および 12大リポジトリ統合無結性ゲート（`verify_repo_total_integrity.ps1`）の Fail-Closed 原則を完全維持します。
- **実行境界**: 外部監査モデル（OpenAI Codex、Anthropic Claude、Local Qwen 27B）の呼び出しは、無出力ストリーミングラッパー（`tools/scripts/call_ai.ps1`）を経由して統制されます。

#### [REQ-OBS-RFC-001] 決定論的リンター多段階化・入力版固定および早期遮断（Fail-Fast）

- **入力**: 監査対象のマークダウン定義書（SRS または RFC）、検証対象行範囲（`LineRange`）、およびパイプライン開始時に算出した対象ファイルの SHA-256 ハッシュを対象とします。
- **処理**: `tools/scripts/run_quad_audit.ps1` において、高コストな外部 LLM（Codex、Claude、Qwen）を呼び出す直前に、ネイティブ高速リンター `VerifySRS.exe`（Stage 1）による構文・DoD・書式チェックを必須実行します。実行開始時に SHA-256 ハッシュを manifest に記録し、各 AI 監査ステージの開始直前にハッシュを再検証して版の同一性を担保します。構文不整合や必須項目の欠落が検知された場合、外部モデルの呼び出しを即座に中止（Fail-Fast）し、不要なトークン消費と API コストを遮断します。差分検証モードが指定された場合も、文書全体の ID 一意性と参照整合性の検査は省略せず Stage 1 で常時実行します。
- **出力**: リンター検証結果レポート（`01_linter_report.txt`）および入力ハッシュ検証証跡を永続化し、検証成功時のみ後続の AI 監査ステージへ遷移します。
- **例外処理**: `VerifySRS.exe` が 1 件以上の `[FATAL]` を返却した場合、または実行中のハッシュ不一致が検知された場合は終了コード 1 で即時停止し、CI/CD およびローカル実行を Fail-Closed で遮断します。
- **完了基準 (DoD)**: 構文違反を含むドラフトに対して Stage 1 で即時遮断されること、検査中のファイル書き換えがハッシュ照合により確実に遮断されること、および正常な仕様書に対してのみ後続 AI 監査が起動することを検証します。

#### [REQ-OBS-RFC-002] 多層 AI 監査官の関心事分離（SoC）および労働法・並行性定量的合否基準

- **入力**: 監査対象仕様書、および各モデルに特化した専門プロンプト・法定算定期待値マトリクスを対象とします。
- **処理**: 外部監査官 3 者（Codex、Claude、Qwen）に対するプロンプトを関心事の分離（Separation of Concerns）に基づき再定義します。OpenAI Codex は「状態遷移機械、DB 排他ロック順序（`member → store → store_staff → attendance`）、並行性デッドロック」、Anthropic Claude は「労働基準法第37条、月60時間超割増（50%加算）、法定休日労働（35%加算、時間外とは排他）、深夜割増（25%加算）、重複加算マトリクス（時間外+深夜=50%、休日+深夜=60%、60h超+深夜=75%）」、Local Qwen 27B は「ドメイン境界、入出力 DTO、回帰的欠落」に特化させます。各モデルは Markdown テーブルおよび構造化 Verdict 形式による簡潔な出力を必須とし、Claude の応答切断（Truncation）検知時は自動破棄して人間介入レビュー（Human-in-the-Loop）フラグを付与します。
- **出力**: 各監査官の専門監査レポート（`02_codex_report.txt`、`03_claude_report.txt`、`04_qwen_report.md`）を独立保存します。
- **例外処理**: モデル応答の切断、必須構造化 Verdict の欠落、または法定割増率マトリクスとの不整合が検知された場合は Fail-Closed で警告を記録し合否判定を保留します。
- **完了基準 (DoD)**: Claude 5.5 が切断なく構造化レポートを出力すること、週40時間超過および月60時間超過の法定加算率が正しく検証されること、および各監査官の指摘重複が抑制され専門分野の欠陥が網羅されることを確認します。

#### [REQ-OBS-RFC-003] デュアルトラック（Track 1 vs Track 2）同期維持および DDL 整合性自動検証

- **入力**: Track 1（ToBe 設計書）、Track 2（As-Built 実装仕様書）の対象マークダウンファイル、および物理スキーマ定義（`schema.sql`）を対象とします。
- **処理**: 実装先行（Track 2）で追加・補正されたドメイン仕様（分割勤務の連鎖再計算、休怠放置デッドロック回復等）を、設計理想（Track 1）へ逆流反映するための差分検出・同期検証スクリプトを配備します。見出しの 1:1 対応検証に加え、仕様書に記載されたテーブル名・列名・一意制約・外部キー制約が `schema.sql` の DDL カタログと機械的に一致することを検証し、文書と DB 実装の乖離を防止します。
- **出力**: 差分比較マトリクス、DDL 整合性突合レポート、およびリポジトリ整合性検証レポートを出力します。
- **例外処理**: Track 1 と Track 2 の間で要件 ID 不一致、または DDL 制約との不整合が存在する場合は Check 3 で検証失敗（Exit 1）とします。
- **完了基準 (DoD)**: Track 1 と Track 2 の要件数が正確に同期していること、DDL 制約の欠落が検出されること、および不一致発生時に統合検証器が Fail-Closed で検知することを検証します。

#### [REQ-OBS-RFC-004] ローカル AI インフラ健全性監視およびフォールバック品質ゲート

- **入力**: 自宅 GPU（RTX 5070 Ti、Tailscale P2P）の接続状態、モデルタグ存在確認（`GET /api/tags`）、および軽量プロンプト応答テストを対象とします。
- **処理**: `tools/scripts/call_ai.ps1` および `audit_with_hermes.ps1` において、主監査インフラ（Tailscale 経由の自社 GPU エンドポイント、`qwen3.8:27b`）に対する TCP 疎通テストに加え、モデルロード状態の事前プローブを実行します。主系障害時にノート PC 内蔵 GPU（RTX 3060 Laptop、ローカルループバック、`qwen2.5:7b`）へフォールバックする際は、監査レポートに `DEGRADED_FIDELITY` ステータスを明記し、最終ゲート判定において人間承認（Human Approval）を必須とする品質ゲート（Quality Gate）を適用します。
- **出力**: 監査実行ログにアクティブな接続エンドポイント、モデルタグ、および品質保証フラグを明記します。
- **例外処理**: 主系および副系の双方が不通の場合、またはプローブ応答がタイムアウトした場合は、パイプラインを即座に停止しネットワーク接続要求を報告します。
- **完了基準 (DoD)**: 主系モデル存在確認プローブが正常に動作すること、副系フォールバック時に `DEGRADED_FIDELITY` が付与されサイレントな品質低下が遮断されることを検証します。
